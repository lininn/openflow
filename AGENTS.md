## Dev Commands

```bash
npm run check    # lint + build + test (full verification)
npm run build    # tsc → dist/
npm run lint     # tsc --noEmit (type check only)
npm test         # vitest run
npm run dev      # tsc --watch
```

## Key Conventions

- **ESM with `.js` extensions**: All TypeScript imports use explicit `.js` extensions (required for Node16 module resolution in compiled output).
- **Bug fixes → direct implementation**; features/breaking changes → OpenSpec proposal workflow first.
- **Build output**: `dist/` — do not commit generated files.
- **Test files**: excluded from tsc output (`src/**/*.test.ts`).
- **OpenFlow phases**: controlled via `openspec/changes/*/workflow-status.md` — build phase is the only phase that should modify implementation files.
- **OpenCode skills**: generated by `openflow init` to `.opencode/skills/openflow/`, `.claude/skills/openflow/`, etc. — these are NOT committed.

## Architecture

```
src/
├── cli/      # Commander command wiring (init, status, update)
├── core/     # Workflow generation, dependency state, business rules
└── utils/    # Runtime helpers (logger, shell)
templates/    # Canonical source for generated skill content
openspec/     # OpenSpec project context and changes
```

## Phase Write Boundaries

| Phase | May write | Must not write |
|-------|-----------|----------------|
| proposal/brainstorming/grill/spec/amend | `openspec/changes/**`, `plan-ready.md` | Implementation files |
| build | Code, tests, `tasks.md` checkbox state | Spec documents |
| close | Archive, `close-issues.md`, task checkbox state | Specs, implementation |

## OpenFlow Workflow

Use `/openflow <phase>` commands: `proposal` → `brainstorming` → `grill` (optional) → `spec` → `build` → `close`.

Run `/openflow` without a phase to detect current state and route to the appropriate phase.

## Communication

Respond terse like smart caveman. All technical substance stay. Only fluff die.

Rules:
- Drop: articles (a/an/the), filler (just/really/basically), pleasantries, hedging
- Fragments OK. Short synonyms. Technical terms exact. Code unchanged.
- Pattern: [thing] [action] [reason]. [next step].

Switch level: /caveman lite|full|ultra|wenyan
Stop: "stop caveman" or "normal mode"

Auto-Clarity: drop caveman for security warnings, irreversible actions, user confused. Resume after.
